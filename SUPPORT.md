## Bugs

For a reproducible software defect, prefer the repository bug-report template.

Before filing:

1. confirm the issue is reproducible on the current Countora version/commit;
2. run `flutter doctor -v` if the problem is build/platform related;
3. search existing issues when practical;
4. remove personal timer/backup data and secrets from logs/screenshots.

Include:

- Countora version/commit
- platform and OS version
- Flutter version for development/build issues
- exact reproduction steps
- expected behavior
- actual behavior
- safe logs if relevant

## Feature requests

Use the repository feature-request template. Explain the real timer workflow/problem being solved rather than only naming a technology.

Countora deliberately avoids features that require unnecessary sign-in, cloud dependency, invasive telemetry, or donation/payment prompts for core functionality.

## Security issues

Do **not** open a public exploit report for a security-sensitive vulnerability. Follow [`SECURITY.md`](SECURITY.md).
